# QQ ChatBot 新手使用教程

把机器人留在你的电脑上，通过 QQ 和它聊天。首次需要填写账号与模型，下载 QQ 组件并扫码；以后通常只需双击程序，有登录失效时重新扫码。

## 1. 下载哪个文件

打开本项目 GitHub 仓库的 **Releases（发布）** 页面，在对应版本的 Assets 中下载 `qq-chatbot-版本号-windows-x64.zip`。这是自带 Python 和桌面依赖的 Windows 绿色包。

不要把 `Source code (zip)` 或不带 `windows-x64` 的源码包当成绿色包。源码包给开发与维护者使用，安装步骤在 README 的“源码运行”。

支持 Windows 10/11 **64 位 x64**；不支持 Windows 7、macOS、Linux 或原生 ARM64。需要可用网络、至少 3 GB 空间和 Microsoft Edge WebView2 Runtime。常见 Windows 11 安装已具备 WebView2，缺失时按下文补装。

右键 ZIP → **全部解压**，放在你有写入权限的短目录，例如 `D:\Apps\QQChatBot`。不要直接在压缩包内运行，不要放在 Program Files。完整保留 `_runtime`、`src`、`config`、`assets`、`_tools` 等文件夹；EXE 不是单文件程序。

双击 **QQ ChatBot.exe**，首次会弹出设置向导。没有弹出时进入 **程序设置 → 首次使用 / QQ 接入**。全文也在 **程序设置 → 新手教程**，不需要打开终端。

## 2. 准备两个 QQ

- **你的 QQ（主人号）**：你平时发消息的账号，机器人只回应这个账号。
- **机器人 QQ**：用于机器人登录的另一个独立账号，不能与主人号相同。

在向导填写这两个号码及希望如何称呼你。账号由你自己准备，程序不注册 QQ，不索取密码。两个账号需要你**手动加好友并确认申请**；程序不会自动通过申请或代你加陌生人。

## 3. 选择一个可用模型

扫码只负责 QQ 登录，不能代替模型服务。以下任选一种，不需要两种都安装。

### 已有 Magpie

在向导选择 **Magpie**，地址固定为 `http://127.0.0.1:3425/v1`。先在 Magpie 中完成你自己的上游模型配置并启动网关；点击“检查 API / 读取模型”，把真实的模型 ID 填入主模型。完整图文说明见程序内 **Magpie 教程** 或 [Magpie 接入教程](MAGPIE_SETUP.md)。

Magpie 自身要求网关鉴权时，按其配置在 Windows 用户环境变量中设置 `MAGPIE_API_KEY`。无需鉴权的本机网关可以不设置；不要为了填空随意编造 token。

### 自有 API，不用 Magpie

选择 **自有 OpenAI 兼容 API**，填服务商给出的 **Base URL**、模型 ID。只支持 OpenAI Chat Completions 兼容协议；不能只因服务名字里有“API”就认为兼容。

Base URL 通常以 `/v1` 结尾，但应以服务商说明为准，不要填 `/chat/completions` 或密钥查询参数。远程接口须为 HTTPS；本机接口可用 HTTP。密钥环境变量名称可用 `HARNESS_API_KEY`，这里填写的是**变量名，不是密钥**。

配置密钥无需终端：Windows 开始菜单搜索 **“编辑帐户的环境变量”** → 在“用户变量”点“新建” → 变量名填写与向导一致的名称，变量值由你自己填服务商密钥 → 保存。彻底退出 QQ ChatBot（托盘 → 退出并停止全部），再重新打开，让进程取得新环境变量。不要把值发给维护 Agent，不要写进人设或截图。

点击 **检查 API / 读取模型** 只读取模型列表，不发送聊天、不产生对话测试。某些服务没有 `/models` 接口，可按服务商说明手填模型 ID。模型还需支持本程序使用的工具调用；视觉辅助模型需支持图片，只有文字模型时可先留空辅助模型。

点击 **保存账号与模型**。修改已有安装时会安全停止聊天，账号改变时停止本项目 QQ；保存不会自动解除暂停。

详细接口与权限说明见 [自有 API 接入](MODEL_API.md)。

## 4. 一键准备 QQ 组件

向导中点击 **下载并准备 QQ 组件**。

**本机已装 QQ 时优先复用**：程序会从 Windows 注册表（`Uninstall\QQ`）和常见安装目录查找已安装的 QQ，找到且版本元数据完整就直接复用它启动机器人，**不再下载几百 MB 的 QQ 客户端**。这个复用只借用 QQ 的可执行文件，机器人账号的登录态仍保存在独立目录（`Documents\Tencent Files\NapCat`），**不会和你日常使用的 QQ 互相串号**。

找不到可用 QQ 时，才从 NapCat 官方 GitHub 和腾讯官方 CDN 下载固定版本，按公开 SHA256 校验后解压到 `.runtime/napcat` 与 `.runtime/qq-client`。

两种情况都**不会修改你平时使用的系统 QQ**。

首次约下载 350 MB（复用本机 QQ 时只需 NapCat 的约 34 MB），解压后约需 1.3 GB 以上，建议至少预留 3 GB。进度就在向导内，可关闭向导后回来查看；下载期间请保留程序运行。中断后重新打开再点下载即可重试，已校验的缓存会复用。

> **复用系统 QQ 的前提**：该 QQ 版本要能被腾讯服务器接受。腾讯当前要求 buildId 不低于 40768，更旧的 QQ 登录会报 `error 45`（版本过低）。程序会在复用前检查这一点，**检测到过旧就自动改用独立客户端**，并提前告诉你原因，不会让你白扫一次码。确实想用本机旧版 QQ，可以升级它，或删掉 `config/local.json` 里的 `qq.client_path` 让它重新下载一份独立客户端。程序不会自动升级你的 QQ。

下载需要你能访问官方来源。程序不会自动换到不明镜像；网络失败时先检查网络再重试。已安装的目录和登录数据不会被覆盖。不要把自己的 `.runtime` 上传 GitHub。

## 5. 扫码登录

点击 **启动并显示二维码**。程序会生成只监听本机的 OneBot 配置并后台启动 QQ，不需要终端窗口。

在手机 QQ 中**切换到机器人账号**，用它扫描向导中的二维码，并在手机上确认登录。请确认账号与向导的机器人号一致。然后切回你的主人 QQ，准备给机器人发消息。

等待向导显示 **机器人 QQ 已在线**。点击 **开始聊天，只回复**，程序才会解除暂停并回应消息。现在用主人 QQ 发一句“你好”，检查能否收到回复。

不需要扫码时，向导会显示已在线。主窗口顶部 **QQ 状态** 也可打开二维码窗口。二维码过期时等待 NapCat 刷新；“刷新状态”只重新读取状态，不保证产生新码。

## 6. 填写专属人设、形象和记忆

- **专属人设**：设置昵称、角色形象、程序图标；导入或编辑 `soul.md`，保存后用于下一轮聊天。
- **长期记忆**：查看、添加或修正记忆。
- **她的日记**：查看、手写日记片段。每日最多三条；自动睡眠整合依赖可用模型与相应时间设置，不是扫码后立即生成历史日记。
- **表情包理解**：配置支持图片的辅助模型后识图，确认你的表情含义。QQ 聊天图片可自动观察，模型推断与人工确认会区分保存。
- **程序设置**：开机自启、关闭收进托盘、深浅主题、窗口行为、备份与诊断。自启默认关闭，需要自己开启。

语音、音乐控制、ADB、联网学习、插件/MCP 属于可选能力，需要额外依赖或授权；绿色包不包含 Whisper 权重或专用设备配置。

## 工作交给外部 Agent

QQ ChatBot只负责聊天陪伴。侧栏“工作转交”支持通用CLI与支持stdio MCP的桌面Agent；填写固定命令/工作目录，或复制MCP配置添加到桌面Agent中。默认关闭，不代你安装、登录或绕过外部Agent审批。

用主人QQ发送 `/工作 具体请求`，或在页面填写并确认。只转交该条文字，不附带完整聊天和记忆。聊天模型的转交建议先成为待确认草稿，桌面Agent还需你明确要求它领取工作。详细设置、取消与回执见[工作转交教程](AGENT_WORK.md)。

## 7. 日常启动、退出与备份

平时双击 EXE 或程序自动创建的桌面快捷方式；勾选自启后在下一次 Windows 登录生效。移动目录后重新打开程序，并重新保存自启开关。

窗口右上角 X 默认收进托盘，QQ 和聊天可能仍在后台运行。要完全退出，使用 **托盘 → 退出并停止全部**。**全部暂停**会立即停止后续发言；不会撤回已经发出的消息。只回复不主动、群里静默等安全规则始终生效。

备份：**程序设置 → 创建快照**，确认后会先停聊天、复制 JSONL 与附件，再启动并保持暂停。完成后自行恢复“只回复”。快照在 `backups` 文件夹；还应复制到其他磁盘。

恢复：在同页选择备份 → 验证 → 恢复，按提示确认。程序保留恢复前快照，恢复后保持服务停止，核对数据再手动启动。记忆与人设在 `data`；QQ 登录在 `.runtime`，不在 JSONL 备份内。更换电脑时可恢复私有 data 和 local.json，但需在新机重新配置自己的密钥环境变量、独立 QQ 路径和扫码。

升级前先备份并完全退出旧程序。将新版**解压到新目录**，再按 [HANDOFF](../HANDOFF.md) 迁移需要的数据；不要直接覆盖整个旧目录，不要把私人目录当发布包。自动升级尚未提供。

## 8. 常见问题

**双击没有窗口 / 提示 WebView2 不可用**：先确认完整解压和有写入权限。从 [微软官方页面](https://developer.microsoft.com/microsoft-edge/webview2/#download-section) 安装 Evergreen WebView2 Runtime 的 x64 版，再打开 EXE。Windows 系统需有正常的 .NET Framework 4.x 与 VC/UCRT 运行库；缺失 VC 运行库时用 [微软官方 x64 安装器](https://aka.ms/vs/17/release/vc_redist.x64.exe) 修复。这些操作由使用者确认，不会悄悄安装系统软件。

**QQ 下载失败**：确认可访问 GitHub 与腾讯 CDN、空间充足，重新点击下载。哈希不匹配时程序会拒绝安装；不要绕过校验。官方包下架或更新结构时需要维护者更新 `config/runtime-downloads.json` 并重新验证。

**没有二维码 / 码过期 / 扫码后 QQ 退出**：先确认账号已保存、组件已就绪，等待 30 秒后刷新状态；查看“运行记录”和“程序设置 → 诊断”。可在“总览”停止全部后从向导重新启动。**若错误称 QQ 版本过低（error 45）**：说明复用的本机 QQ 太旧，请升级你的 QQ，或删掉 `config/local.json` 里的 `qq.client_path` 后重新点“准备组件”，让程序下载一份独立客户端。不要修改系统 QQ、删除登录目录或反复乱换账号。设备验证/风控需要你在 QQ 官方界面处理，程序不能绕过。

**QQ 已连接却不回话**：检查顶部是否暂停、主人号与机器人号是否填反、是否已手动加好友、主模型与 API 是否可用。首次点击“开始聊天，只回复”。只有主人私聊会得到回应，群聊默认静默，其他账号被忽略。限流时稍后再试。

**401 / 没有可用模型**：检查所选 API 的密钥环境变量、权限和模型 ID；改环境变量后彻底退出并重开。Magpie 模式还要确认其网关运行和上游可用。把脱敏错误与版本号交给维护者，不要发密钥。

**本机端口被占用**：在诊断确认归属；不要批量结束所有 Python/QQ。维护者可统一修改配置与 OneBot 端口；向导不会覆盖已有 OneBot 文件。

**找维护者协助**：在程序设置导出脱敏诊断，并提供版本号、操作步骤与错误截图。不要公开 `config/local.json`、`data`、`logs`、`.runtime`、备份或人设文件。

## 9. 维护者发布到 GitHub

请按 [发布说明](RELEASING.md) 使用隐私白名单生成源码包，再上传源码包内容初始化仓库。仓库中的 Windows Actions 工作流能构建绿色包；在 Actions 下载构建产物，或发布版本后由工作流附到 Releases。用户下载的是 Windows 发布资产，不是 GitHub 自动生成的源码 ZIP。

扫码成功属于使用者手机端步骤。当前本机已验证项与未在其他电脑完成的验收，见 [验收清单](ACCEPTANCE.md)；不要把协议测试或旧安装在线当成每位新用户都已成功登录。
