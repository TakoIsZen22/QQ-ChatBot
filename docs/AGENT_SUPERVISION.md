# 任意 Agent 接管与监管

QQ ChatBot不要求安装特定维护 Agent。Hermes、Codex、Claude Code、其他能在用户授权下运行本机命令的 Agent，或人工维护者，都使用相同接口。内置托盘恢复器负责限次拉起意外退出的服务；外部 Agent 负责巡检、解释故障和经用户授权的维护，两者互不替代。

## 1. 交接

将下面的说明交给所选 Agent，并让它在此项目根目录工作：

> 你负责维护这份QQ ChatBot 安装。先读 AGENTS.md、HANDOFF.md 和 docs/ACCEPTANCE.md。先运行 tools/supervise.py --json，只读核对版本、服务、所选模型 API 和已启用的 QQ。没有用户明确授权时，只报告问题，不重启、不改配置、不解除暂停、不发聊天消息。不要读取或索取密钥、QQ 登录态。维护完成按 HANDOFF 的重启、换模型、备份、恢复流程复验，并区分本机实测与外部环境待验收项。

设置页“维护 Agent 名称”只是交接对象的显示名称，保存到 `maintenance.agent_name`。修改它不会自动安装、登录、运行该 Agent，也不会给它授予权限。权限由使用者在自己的 Agent 客户端或操作系统中配置。

## 2. 只读巡检接口

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe tools\supervise.py --json
```

无需进入当前目录的外部调用，应给 Python 与脚本都填入本次安装的绝对路径；脚本自身按位置定位项目，不依赖调用者 cwd。退出码 `0` 表示检查项通过，`1` 表示有服务不可用。固定 JSON schema 为 `dafeiyu.supervision.v1`，包括版本、配置时区时间、维护者名称、overall、checks 和经过筛选的 status。

同一份结果可通过本机 `GET /api/supervision` 或“程序设置 → Agent 监管 → 运行只读巡检”获取。接口仅监听本机，沿用 Host/Origin 检查。输出不含账号号段、聊天、记忆正文、模型密钥或环境变量值。

model_api 检查所选 API 的主机端口；仅 Magpie 模式保留兼容的 magpie 检查键。检查端口与 `GET /api/status` 不代表 TLS、鉴权或模型实际推理成功；暂停、免打扰、长时间安静和 last_spoke 为空均不单独视为故障。巡检不会调用模型、发 QQ、解除暂停、创建定时任务或写入人格数据。

## 3. 定期运行与告警

如需长期监管，使用者在自己选择的 Agent、Windows 任务计划程序或其他调度器中设定频率，调用上面的命令。Windows 任务填写此安装的绝对 Python/脚本路径；不要提交任务导出文件里的个人路径或凭据。

建议仅在状态改变、首次出现问题或恢复时通知用户，同一问题持续期间保持安静；首次启用通知渠道和任何对外发送由用户在该 Agent 中单独授权。本项目不预置通知收件人、不沿用原作者的定时任务、飞书绑定或 Agent 登录态。更换 Agent 时停用旧任务，交接当前故障与最近处理结果，避免多个维护者重复重启。

只读巡检本身不需要修改项目。授予修复权限后再按 HANDOFF 操作；停止意图文件防止托盘守护与人工维护相互拉扯。现有已暂停状态必须保留，恢复回复由用户决定。

程序已移除外部工作绑定，监管仅用于维护本安装，不领取或派发聊天工作。
