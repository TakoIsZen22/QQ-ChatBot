# 群聊监听

适用版本：QQ ChatBot 1.00.02 起。这个入口只读查看群消息；群内 AI 聊天、群记忆及工作转交尚未实现。

## 在程序中使用

1. 先完成「程序设置 → 首次使用 / QQ 接入」，用机器人 QQ 扫码登录。使用者自行把机器人加入需要监听的群；程序不自动加群或同意邀请。开启前告知群成员并遵守群规则。
2. 在左侧「对话」下方点击 **群聊监听 → 添加群监听**，填写真实群号及可选备注。核心保存立即生效；原生QQ白名单在宿主启动时截取，新增/重新启用后需在QQ向导手动停止并启动QQ。
3. 顶部群标签切换单群窗口。选择 **多窗并排** 同时查看所有已添加群；窄窗口自动改为纵向排列。每窗独立滚动，向上看历史时不会被新消息拉到底，点击“有新消息 · 回到底部”查看最新内容。
4. 每个窗口可修改备注、停用/开启监听或移除。停用不采集新消息，已有记录仍可看；移除停止采集并移除窗口，保留本机 JSONL，再次添加同一群可查看。
5. 顶部显示 QQ 连接状态。如果未连接，请先检查 QQ 接入、原生诊断与登录状态（真实群接收尚待验收）。添加群号不会自动加群，也不验证账号是否在该群；只有收到该群事件后才有内容。

默认最多 12 个群，每窗展示最近 100 条。新群从开启后收到的消息开始记录，不读取开启前/断线期间的群历史。重连继续监听，近期消息按群和消息 ID 去重；不会补发、推理或代为回复。

文本、发言人昵称/群名片、成员 QQ、时间分别显示。图片、表情、语音、文件、引用与转发等仅显示类型标记，不下载附件、不转写、不向模型上传；CQ 字符串和 HTML 当普通文字展示。暂不支持群消息撤回同步和编辑同步，已保存内容不会随 QQ 撤回自动删除。

## 数据与边界

- 私有配置：`config/local.json` 的 `group_monitor.groups`，每项为 `group_id/name/enabled`。核心白名单立即更新，原生宿主在下次手动启动时获取新增/重新启用的群；停用和移除立即停止核心采集。高级限制 `max_groups/history_limit/max_text_chars` 在统一配置中；如需调整，停机备份后修改并重启，硬上限分别为 12/500/4000。
- 私有记录：`data/groups/<群号>/monitor.jsonl`，一行一条，包含 `message_id/user_id/sender_name/text/event_time` 和本机保存时间。数据目录可自定义，以本安装 `paths.data` 为准。和其他 JSONL 一起备份恢复；群订阅在配置快照里，恢复数据不会自动覆盖配置。
- 群记录没有自动清理策略，界面只读取有限条末尾记录；维护者应关注磁盘容量，停机后另行归档，不能删除日志、配额或去重文件来修故障。
- 群消息不会进入主人 inbox/chat、soul、长期记忆、日记或 Agent 工作队列，没有群消息发送接口。全局“全部暂停”禁止输出；被动只读监听继续，停止采集请停用对应群或停止服务。“群里完全不说话”始终保留。
- 不读取群成员名单、不抓取群历史、不操作群管理。仅记录机器人既有 本机原生事件流中、被明确列入白名单的群消息。
- 公开源码与 Windows 包默认 `groups: []`，不包含账号配置、订阅群、消息或登录态。

接口与维护地图见 HANDOFF。协议夹具测试不代表真实账号已经连通；本机 QQ 离线时不能验收真实群消息接收。
