# 群聊监听与 AI 回复

适用：1.10.01 / 1.10.02 新源码。默认仅监听，AI 回复需逐群开启；真实 QQ 群收发尚待使用者验收。两个版本使用同一群聊实现，模型仍走所选 API。

## 第一次开启

1. 更新后退出并重新打开桌面，在「程序设置」重启聊天服务，在 QQ 接入窗口手动停止、启动 QQ，加载新版驱动。旧驱动不支持群配置同步；仅刷新页面不够。重启保留原有暂停和群静音，必要时重新扫码。
2. 用机器人账号登录 QQ；由使用者自行把机器人加入测试群。程序不自动加群、同意邀请或执行群管理。先告知群成员并遵守群规则。
3. 左侧「群聊监听 → 添加群监听」填写真实群号和备注，保存。新驱动会即时同步群白名单，无需每加一个群都重启 QQ。顶部须显示 **QQ 已连接、配置已同步**；否则点击「同步群配置」，仍未同步时检查运行记录和是否仍在运行旧驱动。
4. 群窗口点击「群设置」，勾选 **允许本群 AI 回复**，建议选择 **仅 @ 机器人时回复**。填写公开群人设 / 长期说明，仅放允许群成员知道的内容。留空使用默认公开群人设，私人 soul.md 不用于群聊。
5. 主模型 API 配置正确后，由使用者手动开启 **只回复**，点击 **允许群回复** 解除群静音。保存群设置不会自行解除安全开关。
6. 在 QQ 群里使用真正的 @ 选择机器人，随后输入文字，例如「@机器人 你好」。手打昵称、手打 @ 文本或 @全体 不算点名。机器人收到该群的新消息后才具备发送目标；不会发送入群问候。

「每条文字回复」也需显式开启，会把符合条件的新文字送入模型，增加 API 用量；仍受冷却、队列和配额约束，并非每条消息都必然回复。群成员的文字不能修改设置、解除暂停或执行工具。

## 程序内操作

- 单群标签切换，或多窗并排查看多个群；窄窗口自动纵排，每窗独立滚动。向上查看时不强制跳底。
- 「群设置」可编辑备注、触发方式、回复开关、公开人设。关闭本群 AI 回复仍监听；「停用监听」停止采集和回复；「移除」保留本机历史。
- 「重置上下文」让后续模型不再使用该群之前的聊天，历史仍可查看，限流与去重不重置。设置变更或重置会保守取消当时排队和生成中的群轮次；不会补发。
- 「一键群静音」禁止全部群输出，私聊仍按当前模式运行；顶部「全部暂停」禁止所有输出。只读监听继续，停止采集需停用对应群。
- 每窗底部显示最近处理结果；顶部显示 QQ、配置同步、全局暂停与群静音状态。

## 不回复时检查

| 提示或现象 | 处理 |
|---|---|
| QQ 未连接 | 到 QQ 接入检查登录、客户端兼容与网关状态 |
| 配置未同步 | 点击同步；更新源码后需手动重启聊天服务和 QQ，加载新版驱动 |
| 仅监听 | 群设置勾选允许本群 AI 回复 |
| 群静音或全部暂停 | 使用者决定是否开启只回复并允许群回复 |
| 未 @ 机器人 | 用 QQ 的成员选择器真正 @ 机器人，另附文字 |
| 需要文字消息 | 纯图片、语音、表情不触发识图或转写，补一句文字 |
| 冷却中 / 队列已满 | 稍后发送新消息，旧消息不会自动重试 |
| 旧消息不回复 | 仅处理最近 120 秒收到的事件，断线旧消息不补聊 |
| 已取消 | 安全开关、群设置或上下文发生变化，重新发新消息 |
| 回复失败 | 看运行记录中的 group_turn_error / qq_action_error；检查 API 和客户端，确认是否已经发出，程序不重试不确定发送 |
| 模型返回空内容 / 工具请求已忽略 | 检查主模型是否支持正常文字聊天；群没有工具执行入口 |

## 上下文、媒体与隐私

每个群有独立的有限聊天上下文，默认带入最近 12 条已触发对话，成员 QQ 用于区分发言者。普通未触发消息只保存在监听记录，不自动加入模型上下文。不同群不互读；不读取主人私聊、私人 soul.md、关系记忆、日记，不执行插件、MCP、外部 Agent 或工作转交。

「公开群人设 / 长期说明」是手动编辑的持续说明。当前不从群闲聊自动提取长期记忆，没有群记忆候选审批或群管理员聊天命令。

图片、表情、语音、文件、引用与转发仅显示受支持的类型标记，不下载、不识图、不向模型上传，不补拉群历史。文字可以聊天；未实现群内媒体理解、引用回复和撤回同步，已保存内容不会随 QQ 撤回自动删除。机器人仅发送一条纯文本，不发送 @、图片或群管理操作。

## 配置与数据

配置集中于 config/settings.json，私有覆盖在 config/local.json：

| 配置 | 默认与范围 |
|---|---|
| group_monitor.groups | 空；群设置页管理 group_id/name/enabled/reply_enabled/trigger/public_prompt；旧三字段配置仍为仅监听 |
| group_monitor.max_groups/history_limit/max_text_chars | 12 / 100 / 2000，硬上限 12 / 500 / 4000 |
| group_chat.context_messages/queue_size | 12 / 12；允许 0–40 / 1–50 |
| group_chat.cooldown_seconds | 每群接受新轮次至少间隔 15 秒，允许 5–3600，重启不清零 |
| group_chat.max_event_age_seconds/max_reply_chars | 120 秒 / 1000 字；允许 10–300 / 50–2000 |
| group_chat.public_prompt | 默认公开群人设，不超过 2000 字 |
| safety.group_per_minute/groups_muted | 默认每群每分钟 5 条 / 静音；不放宽现有配额，驱动另有每群每分钟最多 5 条硬上限 |

全局 group_chat 参数可在高级配置编辑，保存后重启聊天服务；逐群设置立即同步。修改会保留暂停。默认最多 12 个窗口，每窗显示最近 100 条。

本机私有数据以配置的 paths.data 为根：

- groups/<群号>/monitor.jsonl：被采集的新消息及成功发送的机器人回复。
- groups/<群号>/chat.jsonl：触发对话、模型回复和上下文重置标记。
- groups/<群号>/reply_events.jsonl：未回复原因与处理状态；reservations.jsonl：持久化冷却记录。
- outbound.jsonl：Safety 发言配额；group_spoken.jsonl：最近群发言时间的元数据。

统一备份 data 与附件，同时保存私有配置快照；恢复 data 不自动覆盖当前群设置。停用/移除不删除历史、去重或配额，重启不重试旧轮次。记录没有自动清理，关注磁盘容量，停机后归档。源码与公开发布包默认无群订阅、账号、消息或登录态。

验收与回滚见 HANDOFF 和 ACCEPTANCE；本机协议夹具通过不等于真实群收发已通过。
