# QQ 接入：扫码与账号密码

适用 1.10.01 / 1.10.02。QQ ChatBot 使用原创 Windows 宿主与适配层加载固定官方 QQ 内核；向导可下载组件，选择扫码或机器人 QQ 账号密码登录。不需要另装外部桥接程序。QQNT 内部接口不是稳定公共 API，每份安装都需要验证实际收发；当前限制见 [原生桥接](NATIVE_QQ.md)。

## 程序内操作

1. 打开“程序设置 → 首次使用 / QQ 接入”。准备两个不同的 QQ：主人号给机器人发消息，机器人号用于登录。由你手动加好友，不自动同意申请。
2. 填称呼、两个 QQ 号、Magpie 或自己的兼容 API、真实模型 ID，保存。这里只填密钥环境变量名称，密钥由你在自己的服务或 Windows 环境变量中配置。
3. 可先点击“检测本机 QQ 兼容性”：已适配且关键文件校验通过时，可将程序文件复制到独立目录，另行扫码。未适配时点击“下载并准备 QQ 组件”，使用已兼容的官方客户端。两种方式都不修改日常 QQ、不读取其登录态；已有同版本或不完整目录不覆盖。详见 [多版本兼容说明](QQ_COMPATIBILITY.md)。
4. 在第 3 步选择“扫码登录”或“账号密码”。扫码时点“扫码接入”，用手机机器人账号扫描并确认；账密时输入机器人 QQ 密码，点击“登录 QQ”，程序会启动独立 QQ 并提交给官方内核。过期可刷新二维码；扫错号则停止接入后重启。不要向任何人提供登录二维码、凭据或登录文件。
5. 等界面显示机器人在线。先从主人号发文字检查接收，再由你点击“开始聊天，只回复”。程序不会自动解除暂停；暂停时测试消息不会自动补回，恢复后发一条新消息。
6. 每次宿主重新启动后先由主人发消息，使程序取得已校验的主人 UID。模型配置成功与 QQ 登录成功是两项独立检查。

Windows 包已内置自写宿主。源码用户还需按 [构建说明](WINDOWS_BUILD.md) 编译宿主，否则按钮不可用。新机器仍需自己的网络、手机确认及可能的设备验证，不能借用作者登录态。

## QQ 密码、验证与自动登录

QQ 接入窗口（顶部 QQ 状态按钮）和首次向导都提供两个登录方式。本机程序锁的账号密码与 QQ 密码分别管理；此前设置的本机账号不能用来登录 QQ。机器人 QQ 号只读，需修改时在首次向导第 1 步保存。

- “记住 QQ 密码”“启动程序时自动登录 QQ”默认关闭，自动登录需先勾选记住。保存后密码框留空可使用缓存，不将密码回填界面；“忘记已保存的 QQ 密码”仅清除缓存与自动登录，当前在线会话保留。
- Windows 当前用户 DPAPI 加密保存协议登录材料到私有 `.runtime/qq-password.local.json`；它等同凭据，不能公开或随包分发。绑定当前安装路径和机器人号，默认 30 天（`account.remember_days`）。只保留协议所需摘要的加密密文，不保存明文 QQ 密码；不会送给模型或写入配置/应用日志。
- 自动登录只在桌面本次进程首次进入主界面时尝试一次。已有 QQ 宿主运行时保留其流程；在程序中主动停止 QQ 会关闭自动登录，之后需手动登录并重新勾选。人工停止服务的运行意图也会阻止自动登录，需手动启动服务后重新打开界面；停止全部不会被监督程序拉起。只退出界面可保留在线 QQ。
- 腾讯要求滑块时点“打开安全验证”，在独立窗口操作。需要设备确认时打开腾讯验证页，完成手机操作后点“我已完成设备验证”。验证窗口只可提交一次验证码结果，没有程序管理接口；不会代做验证。
- QQ 可能拒绝账密、要求扫码或当前内核不支持；可随时回到扫码方式。密码请求间隔至少 5 秒、每次宿主最多 10 分钟 5 次；验证默认 120 秒到期。内核无响应时手动停止再启动，不自动连续提交。换登录流程后，旧验证结果不能继续使用。

更新源码后，先从托盘“仅退出界面”再双击 QQ ChatBot 打开新界面。现有 QQ 会话不会自动退出；若显示“进程尚未加载账密登录”，需要你在接入窗口手动停止 QQ 后重新启动一次。此次会重新登录，但不删除 profile、限流或消息记录，安全模式保持原样。

当前扫码在此前本机安装实测通过；新增账密与验证码使用离线协议夹具及隔离 WebView2 测试，**真实 QQ 密码、滑块/新设备验证、重开自动登录仍需使用者在本机验收**。新版源码不等于 GitHub 旧安装包已更新。

## 日常使用与群监听

开机自启与桌面异常恢复默认只启动聊天核心。未启用 QQ 自动登录时，手动选择扫码或账密；启用后，桌面首次解锁加载时只尝试一次，不循环重登或解除暂停。关闭界面到托盘或仅退出界面不会停止已有 QQ；“退出并停止全部”停止本安装核心与 QQ，不结束其他 QQ。

侧栏“群聊监听”添加机器人已经加入的群，可单窗或多窗查看。默认仅监听；在群设置逐群开启 AI 回复、填写公开人设，再手动开启只回复并允许群回复。更新后首次重启聊天服务和 QQ 加载新版驱动，之后增改群即时同步；顶部显示同步结果。群模型只读取本群触发对话，不读取私人资料。真实群收发需另外验收，步骤与排查见 [群聊教程](GROUP_MONITOR.md)。

当前支持主人文字入站与文字发送接口；发送仍需本次真实验收。群文字回复已有实现与夹具，真实群收发待验收；历史补拉、QQ语音取文件、发送图片未实现。本机语音转写和本机图片上传独立可用，不等于QQ媒体已经接通。

## 排障与维护

源码在项目根运行；Windows 包改用 .\_runtime\python.exe：

```powershell
.\.venv\Scripts\python.exe tools\qq-native.py doctor
.\.venv\Scripts\python.exe tools\qq-native.py status
```

doctor 只读检查固定文件哈希、自有进程与本机状态，不发消息、调用模型或读登录态。登录与连接错误不能靠换模型 token 解决。不要运行项目内 QQ.exe 代替自写宿主，不要改 package.json、关掉哈希校验或删 profile/限流/日志。

正式流程不需要 prepare；该命令仅保留给旧实验安装回滚。若诊断要求恢复旧入口，先停止 QQ，再显式执行 tools/qq-native.py restore。完整路径、阶段和恢复说明见 [NATIVE_QQ](NATIVE_QQ.md)。
