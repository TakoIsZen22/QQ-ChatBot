# 本机账号与密码登录

适用于 QQ ChatBot 1.10.01 和 1.10.02。这是当前安装的可选程序锁，单个账号；不会注册云端账号，也不是 QQ 的账号密码登录。QQ 可在独立接入窗口选择扫码或 QQ 账密，详见 [QQ 登录教程](QQ_SETUP.md)；两个账号和密码缓存互相独立。模型 API 接入方式不变。

## 设置和日常使用

1. 更新源码后完全退出桌面界面，再重新打开。若聊天服务仍运行旧代码，先在总览重启聊天服务，保持全部暂停；旧服务没有账号校验时，程序会拒绝设置账号并提示重启。
2. 打开「程序设置 → 本机账号与锁定 → 设置本机账号」。填写自己的账号、密码及确认密码，点击「保存账号」。没有默认账号或默认密码，不需要把密码发给维护者。
3. 账号为 1～64 字的单行文本；密码为 8～128 个字符。密码使用本机 scrypt 加盐哈希保存，不写入聊天、模型请求、QQ 消息或日志。
4. 设置或登录时可以勾选「记住密码」「自动登录」，默认不勾选。自动登录需要记住密码；未选自动登录时，重开会显示已保存的账号和“已记住密码”，点击登录即可，不将保存的密码填回网页输入框。也可直接输入新的密码。
5. 勾选自动登录后，正常退出界面再重开，可在当前 Windows 用户下自动进入。顶部「锁定」、设置卡片「立即锁定」或默认收进托盘时，会关闭自动登录；下次需手动点击登录或输入密码，重新勾选才再次启用。锁定不会被自动登录立即解除。修改账号或密码需输入当前密码，保存后其他已登录会话失效；可同时选择保存新密码。
6. 密码连续输错默认 5 次后冷却 5 分钟，重开程序不能清除冷却。一次登录默认有效 12 小时，到期需要登录；自动登录仅在桌面进程首次加载时尝试一次，不在会话过期或手动锁定后反复尝试。账号是每份安装独立的，不是多用户记忆空间。

记住密码使用 Windows 当前用户的 DPAPI 加密，默认保存 30 天（`account.remember_days` 可设 1～90）。加密绑定当前安装路径；复制到另一台机器、Windows 用户或路径后需手动输入。损坏、到期、账号版本变化或自动登录被冷却拒绝时，退回手动登录，不反复重试。没有 Windows 加密能力时不提供明文回退。程序设置的「忘记已保存的密码」只清除加密缓存与自动登录，不删除本机账号、失败记录、审计或聊天。

浏览器打开本机聊天页面时使用同一个账号；登录会话放在 HttpOnly、SameSite=Strict Cookie 中。桌面会话只保存在进程内存，另行勾选的密码由 Windows 加密保存，不写 localStorage、Cookie 或日志。浏览器版不提供这份桌面密码缓存。锁定会同时作废这份安装中的其他桌面/浏览器会话，其他窗口会在下一次请求或约 5 秒内转回登录页。

锁定保护界面和私人 API 的访问，**不会暂停已有后台聊天**。登录页仍可「全部暂停」；托盘仍可停止服务，不能在未登录时恢复只回复、启动服务或读取私人记录。开启账号后，冷启动的服务自动启动和异常恢复会先等待登录；登录后可在总览手动启动。开机自启仍可用于启动锁定的程序入口。

未登录的维护脚本仍可查精简健康状态、暂停与停止；`tools/manage.py reply-only` / `active` 会被拒绝，改由使用者登录桌面后切换模式。不要为维护导出密码或会话。

这不是磁盘加密：拥有 Windows 文件访问权限的人仍可读取 JSONL、配置和备份。应同时使用 Windows 账户锁屏与磁盘权限。不要把本机管理端口转发到公网。

## 文件、配置和备份

| 位置 | 内容 |
|---|---|
| `config/account.local.json` | 私有账号、密码哈希、会话校验材料；不存明文密码 |
| `.runtime/account-remember.local.json` | 可选 Windows DPAPI 密文，包含保存的登录信息和有效期；不含明文，不公开、不随数据快照迁移 |
| `.runtime/account-attempts.json` | 持久化输错次数与冷却时间，不因重启而删除 |
| `.runtime/account-logs/events.jsonl` | 带时间和层级的设置/登录成功/失败/修改/锁定事件；不记输入内容 |
| `config/settings.json` 的 `account` | 统一默认策略，可经 `config/local.json` 覆盖，更新后重启界面及聊天服务 |

策略字段：`session_seconds=43200`、`remember_days=30`、`max_failures=5`、`failure_window_seconds=900`、`lockout_seconds=300`、`lock_on_hide=true`。记住密码及自动登录是使用者逐次选择的本机状态，不是公开默认开关。账号启用以私有账号文件存在为准，公开配置不放账号密码。

现有维护备份会复制完整 `config/`，因此包含账号文件；备份必须私下保存，不能上传 GitHub。普通「恢复」只恢复 data，不覆盖当前账号或配置。`.runtime` 的账号限流和审计日志不在 data 快照里，原位恢复时保留原文件；完整迁移如需审计记录，停机后另行私下复制。

若人工恢复旧 `account.local.json`，该文件对应的旧会话可能重新有效：停止所有本项目进程后恢复，在重新开放界面前登录并修改密码，使旧会话作废。账号文件、临时写入文件、限流记录和日志都已被 Git/公开发布白名单排除。

## 忘记密码或账号文件损坏

没有云端找回或万能密码。具有本机目录控制权的安装所有者可离线重设；此步骤会暂时关闭程序锁，应在自己的 Windows 会话内完成。

1. 用托盘「退出并停止全部」停止本项目程序，确认聊天和 QQ 宿主已停；不要结束其他 QQ/Python 程序。若界面无法打开，源码安装用 `tools/stop.bat` 停止核心，再退出托盘；绿色包可在安装目录执行 `_runtime/python.exe tools/manage.py stop`，再退出界面。
2. 保留当前私有备份，在安装目录执行以下 PowerShell。只重命名账号文件，不删除 data、日志、限流、QQ profile 或历史。

```powershell
# 先进入自己的 QQ ChatBot 安装目录；不要在其他目录执行。
$accountPath = Join-Path (Get-Location) 'config\account.local.json'
$recoveryName = 'account-recovery-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.local.json'
Rename-Item -LiteralPath $accountPath -NewName $recoveryName -ErrorAction Stop
```

3. 重新打开程序，保持全部暂停，在「程序设置」重新设置账号。原文件的改名副本仍属私密文件，不上传、不发给他人。旧限流记录继续保留，若尚在冷却期，等待结束再试。
4. 检查新账号可锁定和登录后再由使用者恢复需要的聊天模式。旧备份中的账号不应直接覆盖新账号。

若只是限流文件损坏，先停机并私下保留异常文件，与可信的同一安装备份比较恢复；不要通过删除失败记录绕过正常冷却。

## 验证与回滚

单元/HTTP/真实 Windows DPAPI 验收：`python -m unittest tests.test_local_account tests.test_remembered_login -v`。隔离 WebView2 验收：桌面环境运行 `python tools/smoke-local-account.py`。均使用临时账号，不访问真实 QQ 或模型。

回滚旧源码前先停机并保留私人账号文件、限流、日志和 data。旧版本没有登录校验，运行旧代码即不再提供此程序锁；不要把旧版继续当作已受保护的界面。不要在发布包中携带当前账号文件。
