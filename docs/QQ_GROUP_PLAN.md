# QQ 群回复方案（设计稿，尚未实现）

> 已单独实现[只读群监听窗口](GROUP_MONITOR.md)，由使用者显式添加群后保存实时新消息；不调用模型，不自动聊天或转交工作。本文的 @ 回复、群记忆和审批仍为设计，不能作为已实现功能使用。下文“默认不采集”指未开启监听/未明确授权的群。

适用版本基线：QQ ChatBot 1.00.02。本文只提出方案，不修改现有运行配置，不加入群、不发送群消息、不连接真实 Agent。

## 1. 产品定位

在群里担任有明确边界的聊天伙伴：被叫到时聊天、理解本轮表情、记住群内明确确认的共同约定；不承接工作执行或外部工作转交。

推荐默认策略：**白名单群 + @才回复 + 群记忆隔离**。

## 2. 群内体验

使用者自行邀请机器人 QQ 入群，不自动加群或同意邀请。在桌面“QQ群”页添加群号并开启该群后，成员可使用：

```text
@机器人 今天好累，陪我聊两句
@机器人 [表情包] 这张图什么意思
@机器人 /记住 我们每周五晚一起看电影
```

这些是拟议交互，当前版本未支持。

普通消息默认不参与聊天，不落入记忆、不调用模型。触发按结构化@片段判断，不凭昵称子串判断。可选“回复机器人消息继续聊”，需验证引用的是本机记录的机器人发言。

每次默认回复一条短消息，必要时至多两条，引用触发消息；不主动插话、不主动私信群成员、不@全体、不代管群或自动拉人。

## 3. 身份与权限

| 身份 | 默认权限 |
|---|---|
| 普通群成员 | 在已启用群内@聊天；提交群记忆候选 |
| 配置中指定的本群管理者 | 管理本群安静状态、审核本群记忆；不能取得主人私聊或其他群权限 |
| 安装主人 | 在桌面启停群、指定管理者、审核群记忆；使用全局保命开关 |

管理者名单由主人在程序中配置，不能靠群昵称、“我是群主”的文字声明或转发内容获得权限。QQ原生群管理员身份不自动获得本程序的配置权限。

群里的“闭嘴/停”不能沿用私聊逻辑，让任意成员暂停整个程序。未授权成员最多结束自己的当前会话；本群静默由本群指定管理者或主人控制；全局暂停只接受桌面操作或主人已授权控制入口。

## 4. 人设、上下文与记忆隔离

当前Harness把所有对话视为owner；群接入须先拆分actor与scope：

- 私聊主人：现有私人soul、关系、日记和记忆继续只用于私聊。
- 群公共角色：使用单独的“群人设”，不自动带入私人soul、主人称呼/印象、私聊日记或私人关系设定。
- 群会话：按群号、成员号、触发消息/会话标识隔离；仅纳入该成员本轮明确发送/引用的相关内容。
- 群长期记忆：按群号隔离，只保存明确确认的共同事实与约定；默认由主人/指定本群管理者审核，不从全群闲聊自动抽取。

默认不收集未触发的群闲聊，也不把其他成员的聊天自动发给模型。若以后提供群上下文窗口，需单独说明范围并由使用者开启，不能静默启用全群采集。

建议数据仍为本机JSONL，分区如 `groups/<group_id>/chat.jsonl`、`memory.jsonl`、`memory_candidates.jsonl`，存取接口强制带scope。界面支持查看、修改、删除标记与按群备份；不能仅靠提示词避免跨群泄漏。

## 5. 聊天边界

群功能仅规划聊天、表情理解与隔离记忆，不规划外部 Agent、CLI 或工作转交。

## 6. 限流与保命

建议保守默认值，均集中在配置并可在程序内修改；既有安全上限不能放宽：

| 范围 | 建议默认 |
|---|---|
| 整个机器人账号发言 | 所有通道合计最多20条/分钟 |
| 每个群发言 | 最多5条/分钟，每个气泡均计数 |
| 单个成员连续触发 | 间隔至少15秒，防止一个人占满群队列 |
| 一轮群回复 | 通常1条，最多2条短消息 |
| 自动主动群聊 | 默认关闭 |
| 模型并发 | 建议最多2个请求，主人私聊优先，不无限排队 |
| 不可撤回操作 | 保持至少10分钟一次、每天最多3次；第一版不开放群管理/公开评论等动作 |

增加群级每日模型调用预算与全局预算；预算触顶停止新调用，不反复刷提示。排队过久的群请求过期后不补发。限流与去重记录落盘，重启不能重置配额或重复回应。

保留三层开关：**全部暂停 / 所有群静默 / 单群静默**。发出每个气泡之前重新检查群权限、配额和取消世代，保证开关生效后不继续发送队列里的气泡。已发出的消息与外部执行副作用不能撤销。

## 7. 桌面程序入口

新增“QQ群”页面，提供：

1. 群白名单与单群开关；默认全部未启用。
2. 触发方式、群人设与本群管理者名单。
3. 群回复长度、冷却、额度和免打扰时段。
4. 群记忆候选审核、已确认记忆和聊天记录查看。
5. 所有群静默与单群静默按钮；显示未启用群不会被处理。

每个群的配置和记录明确显示所属群；私人soul页保持私人范围，不与群人设共用保存按钮。群启用时显示该群数据处理说明，建议由使用者在群内说明机器人如何触发、保存什么以及由谁审核。

## 8. 必要的代码变更

| 部分 | 当前状态 | 需要补齐 |
|---|---|---|
| `modules/qq_bridge.py` | 过滤全部群消息；动作白名单只有私聊发送 | 白名单群过滤、结构化@/引用触发、群目标发送；忽略自身消息及未启用群 |
| `core/harness.py` | `person='owner'`，聊天/图片/语音/提示组合都围绕主人 | 引入actor、scope、reply_target；分离私聊与群提示及上下文 |

| 本机API与桌面桥 | 已有只读群监听配置与消息窗口 | 增加候选审核和受控回群接口 |
| 备份/监管/文档 | 全量data快照与只读状态 | 纳入群分区、群开关/待审计数；不在巡检输出群正文或成员私密信息 |

现有的`groups_muted`和`group_per_minute`只是部分安全基础，不能据此声称已支持群聊。尤其不可直接把群事件送进现有owner提示或将群回执退回主人私聊作为通用兜底。

## 9. 分期落地与验收

第一步：完成scope隔离、白名单群、@聊天、短回复与三层静默。使用本机协议夹具验证，然后在使用者自己的小型测试群验证收发。

第二步：群专用人设、群内图片理解、记忆候选审核与程序内编辑。放入私聊测试标记，验证群回复和群模型请求中都不会出现；验证不同群和不同成员不串会话。


验收还须覆盖：未启用群零模型请求、伪造昵称/@文本不触发、非管理者不能全局暂停、账号及群配额、自己消息不循环、断线后旧消息不刷屏、去重跨重启保留、受保护私人资料不进公开包。真实QQ群实连单独记录，不能用夹具结果替代。
